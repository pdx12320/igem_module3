# APOBEC 编辑模块 · 计算工作流代码包

> 交付对象：队长（用于统合）
> 内容：本项目 APOBEC 编辑模块（"保 G 排 A"）全部计算工作用到的 **88 个 Python 脚本 + 2 个 shell 脚本**，
> 按 **13 个工作阶段 + 1 个废止存档**整理，并附工作流说明、脚本清单与数据依赖说明。
> 配套数据：Dry Lab 页面的绘图数据包（`APOBEC_DryLab_绘图数据包.zip`）与本包分开交付。

---

## 1. 这个包是什么

这是把工作目录里散落的脚本**原样收拢、只做归类与说明、不改动任何代码**之后的成果。
文件名一律保留原始编号（`07_mcsm_rerank.py`、`analyze_batch3.py` …），因为项目报告、图注与数据字典
里引用脚本时用的就是这些名字——改名会让那些引用失效。

包内文档分工：

| 文件 | 内容 |
|---|---|
| `README.md` | 本文件：包的用途、怎么跑、依赖、约定 |
| `WORKFLOW.md` | **工作流主线**：13 个阶段各自解决什么问题、输入什么、输出什么、依赖谁 |
| `MANIFEST.md` | **逐脚本清单**：每个脚本的用途、行数、第三方依赖、读写的文件 |
| `DATA.md` | 数据依赖：脚本读写的目录与文件、体量、外部工具（AF3 / mCSM-NA / PremPRI） |
| `requirements.txt` | Python 依赖清单 |
| `_tools/build_package.py` | 本包的生成脚本：重新收拢脚本、重新生成 MANIFEST。**统合后如需增删脚本，改这里再跑一次即可** |

## 3. 怎么跑

### 3.1 环境

```bash
pip install -r requirements.txt
# 或使用 uv（本项目开发时的用法）：
uv run --with numpy --with openpyxl python <脚本>.py
```

多数脚本**只用标准库**（`ast`、`csv`、`hashlib` 等）；需要 `numpy/scipy/matplotlib/openpyxl` 的
集中在 S5–S12。`MANIFEST.md` 里每个脚本都标了它自己的依赖。

两个需要注意的环境限制：

- `pptx_build.py` 用 **PowerPoint COM** 组装 PPTX，**仅 Windows 且需安装 Office**。
- `57_make_wiki_figures.py` 与 `plot_drylab_figures.py` 用 Noto Sans CJK SC 字体；
  `plot_drylab_figures.py` 还会用 `fonttools` 把可变字体实例化成静态字重（本机 Noto Sans SC 只解析到 Thin）。

### 3.2 运行方式

脚本设计为**在项目根目录执行**，读写相对路径（如 `results/`、`af3_submit/`）。
把本包的 `code/<阶段>/*.py` 放回项目根目录（或保持原目录结构）后即可运行：

```bash
python 00_manifest.py       # 从这一步开始
python 01_qc.py
...
```

各脚本之间**不是链式管道**，而是共享同一批中间文件：上游产出写进 `results/`，
下游脚本按文件名读取。因此重跑某个环节时，只要它依赖的上游产物还在，就可以单独跑。
`WORKFLOW.md` 标明了每个阶段的上下游。

> **没有提供一键 `run_all`**：原因是流程中有 3 处需要**人工/外部工具介入**
> （AF3 服务器提交、mCSM-NA / PremPRI 网页提交、湿实验数据回收）。
> 强行串成一条命令会产生"看起来跑通了、实际用的是旧数据"的假象。这是刻意的。

## 5. 三条需要一并交代的约定

1. **数据文件不在本包内。** 本包只含代码。原始结构文件（`GUGCGCG_20/` 等，各约 112 MB）、
   测序数据（`Seq/`、`组合突变结果/`）与中间结果（`results/`）体量远大于代码，
   且属于项目数据资产而非可分发代码。**《DATA.md》逐项写明了每个脚本需要什么数据、在哪里。**
2. **保留原始编号、保留废止脚本。** `_cancelled/` 里的两个脚本已不再使用，但保留是为了让
   早期报告里的引用仍可追溯。**请勿在统合时删除或重编号**，否则报告与代码的对应关系会断。
3. **不合并、不重构。** 包内代码与工作目录中的版本逐字节一致（除本说明文档外无任何改动）。
   统合时如需合并重复逻辑（例如多个脚本里各自实现的读取 `results/` 的函数），
   建议新建一层共用模块，而不是就地改这些脚本——报告里的数值是由这些脚本的当前版本产出的。
